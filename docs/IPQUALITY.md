# xykt/IPQuality 接入

核对日期：2026-10-27。上游项目：[xykt/IPQuality](https://github.com/xykt/IPQuality)。官方 README 中的 `https://IP.Check.Place` 本来就是该项目的运行入口；CqShell 现在用专用操作明确标注项目，并直接从 GitHub 固定修订获取入口脚本。

## 操作

- TUI：服务器测试 → IP 质量体检 · xykt/IPQuality。
- CLI：`cqs run test.ip`。
- `ip_family=dual|ipv4|ipv6`，默认 dual；分别不添加协议参数、添加 `-4`、添加 `-6`。
- `full_ip=off|on`，默认 off；on 添加 `-f`。
- 简体中文界面传入 `-l cn`，英语及其他界面语言传入 `-l en`。上游完整报告自身提供中英文模板，不使用本地语言包重新解释其检测结果。
- 固定传入 `-p`，不生成/上传上游在线报告；这不阻止风险数据库、流媒体、邮件、统计或参考文件等正常外部请求。

检测模块及评分直接来自上游，包括基础信息、IP 类型、风险评分/因子、流媒体/AI 服务访问、邮件连通和黑名单等。CqShell 不伪造评分，不把常驻面板里的公网 IP / ISP 查询当作质量检测。

## 执行边界

1. 校验参数，仅接受固定枚举，不透传任意 shell 参数或代理口令。
2. 显示来源与依赖/网络访问说明，确认后下载到私有临时目录。
3. 限定 HTTPS 请求和重定向，要求完整非空下载。
4. 校验入口脚本的 SHA-256，再运行真实 `bash -n`，失败则不执行。
5. TUI 交还终端，使用参数数组运行 Bash 和脚本；保留上游排版及交互。上游非零退出码会作为失败返回；结束后返回 TUI。

不传上游 `-y` 自动安装依赖或 `-n` 跳过依赖检查。CqShell 的 `--yes` 只作用于本工具确认，不代表同意上游安装依赖。缺少 jq、bc、netcat、dig 等依赖时，上游可能询问安装并要求 root/sudo。该操作因此不标为纯只读。

本接入沿用 CqShell 的 Debian / Ubuntu 原生执行范围。上游另有 Windows Docker 运行方式，但本次未接入 Docker 执行路径，避免把容器网络结果误称为 Windows 主机结果。
